Use this path to evaluate Querylane with 1 PostgreSQL server you already understand. You will start the preview, configure Querylane's own storage, register a server, and verify 1 operational answer.

:::tip
Start with a non-production server and a dedicated read-only PostgreSQL login. Familiar data gives you a reliable baseline for checking what Querylane shows.
:::

## 1. Start Querylane

The fastest path is the Docker quick start. It starts Querylane, its metadata database, and a demo PostgreSQL server with a live workload, and needs only Docker:

```sh
curl -fsSL https://raw.githubusercontent.com/querylane/querylane/main/deploy/quick-start/compose.yaml | docker compose -f - up
```

Open `http://localhost:8080`. Querylane lands on the preconfigured **Demo: Ecommerce** instance, so you can skip to [step 4](#4-complete-a-useful-first-session). See [Install with Docker](/get-started/install-docker) to add your own server, or [Install with Helm](/get-started/install-helm) for Kubernetes.

To evaluate against a PostgreSQL server you already have, run the image on its own:

```sh
docker run --rm \
  --name querylane \
  --publish 127.0.0.1:8080:8080 \
  ghcr.io/querylane/querylane:latest
```

Open `http://localhost:8080`. A fresh container has no metadata database configuration, so Querylane opens the first-launch wizard.

:::warning
`docker run --rm` removes the container when it stops, and the quick start hard-codes credentials. Use them for evaluation, not a durable deployment.
:::

Tagged releases produced by the release pipeline also include self-contained binaries. Until the first binary release is available, use the Docker preview to evaluate the product and pin its digest anywhere repeatability matters.

## Download a release binary

Each tagged binary release includes the compiled web application and needs no separate frontend runtime. Open [Querylane releases](https://github.com/querylane/querylane/releases), choose a version, and select the archive for your system:

| System | Archive suffix |
| --- | --- |
| Apple silicon macOS | `darwin_arm64.tar.gz` |
| Intel macOS | `darwin_amd64.tar.gz` |
| ARM64 Linux | `linux_arm64.tar.gz` |
| AMD64 Linux | `linux_amd64.tar.gz` |
| AMD64 Windows | `windows_amd64.zip` |

On macOS or Linux, replace `1.2.3` below with the release version:

```sh
set -eu

version="1.2.3"

case "$(uname -s):$(uname -m)" in
  Darwin:arm64) target="darwin_arm64" ;;
  Darwin:x86_64) target="darwin_amd64" ;;
  Linux:aarch64 | Linux:arm64) target="linux_arm64" ;;
  Linux:x86_64) target="linux_amd64" ;;
  *) echo "Unsupported system: $(uname -s) $(uname -m)" >&2; exit 1 ;;
esac

archive="querylane_${version}_${target}.tar.gz"
release_url="https://github.com/querylane/querylane/releases/download/v${version}"
curl --fail --location --remote-name "${release_url}/${archive}"
curl --fail --location --remote-name "${release_url}/checksums.txt"

checksum_line="$(awk -v archive="$archive" '$2 == archive { print }' checksums.txt)"
if [ -z "$checksum_line" ]; then
  echo "No checksum found for $archive" >&2
  exit 1
fi

if command -v sha256sum >/dev/null 2>&1; then
  printf '%s\n' "$checksum_line" | sha256sum --check
else
  printf '%s\n' "$checksum_line" | shasum --algorithm 256 --check
fi

tar --extract --gzip --file "$archive"
mkdir -p "$HOME/.local/bin"
install -m 0755 querylane "$HOME/.local/bin/querylane"
"$HOME/.local/bin/querylane" --version
"$HOME/.local/bin/querylane" server start --host 127.0.0.1
```

Add `$HOME/.local/bin` to `PATH` if you want to run `querylane` without its full path. Windows users can verify the downloaded ZIP against `checksums.txt`, extract `querylane.exe`, and place it on `PATH`.

## 2. Configure Querylane storage

The wizard configures **Querylane's metadata database**. This is separate from the PostgreSQL instance you want Querylane to inspect.

| Storage | Use it for |
| --- | --- |
| Embedded PostgreSQL | A direct local run or disposable demo |
| External PostgreSQL | A durable installation |
| Manual YAML | Configuration-as-code and environment-backed secrets |

For this disposable container, choose external PostgreSQL if one is available. Embedded PostgreSQL is better for a direct host run because the process and data directory must survive together. See [Configure Querylane](/get-started/configure-querylane) before keeping an installation.

## 3. Register a PostgreSQL instance

<Steps>
  <Step title="Open Add instance">
    Onboarding sends you to the instance form. Later, use the instance switcher to add another server.
  </Step>
  <Step title="Enter the connection">
    Provide a display name, host, port, initial database, username, password, and SSL mode. You can paste a complete PostgreSQL DSN instead.
  </Step>
  <Step title="Test the connection">
    Querylane requires a successful test before registration. Changing the connection invalidates the previous test.
  </Step>
  <Step title="Register the instance">
    Querylane stores the connection, discovers server information and databases, and opens the instance overview.
  </Step>
</Steps>

If the test fails, check DNS and network access, the initial database, credentials, PostgreSQL `pg_hba.conf`, and SSL mode. Querylane returns a generic connection failure unless an administrator configured a strict target allowlist.

## 4. Complete a useful first session

Do not stop at a green connection. Use the instance to answer a question you can verify elsewhere.

<Steps>
  <Step title="Confirm the server baseline">
    Check connection state, PostgreSQL version, connection capacity, health warnings, and the sample timestamp.
  </Step>
  <Step title="Find an object you know">
    Open a database and schema, then confirm the columns, indexes, constraints, policies, or triggers of a familiar table.
  </Step>
  <Step title="Answer 1 live question">
    Review Activity for active sessions, old transactions, waits, or blockers. Or inspect a known role's memberships and grants.
  </Step>
  <Step title="Verify the answer">
    Compare the result with `psql`, an existing dashboard, or a catalog definition you trust.
  </Step>
</Steps>

## You are successful when

- The connected instance is the server you intended to register.
- You can navigate to a known database, schema, and object.
- You can explain at least 1 health, activity, structure, or access finding.
- The finding agrees with another trusted source.
- You understand whether missing information is caused by the registered PostgreSQL role's permissions.

Continue with [Use Querylane](/use-querylane) for the product tour. Before adding production credentials, follow [Deploy Querylane](/get-started/deploy-querylane).

## Run from source

Use the source path for contributor work or to test an unreleased change. Install Go 1.26, Bun 1.3, [Task](https://taskfile.dev/), and Git.

```sh
git clone https://github.com/querylane/querylane.git
cd querylane
task setup
task dev:setup
task dev
```

To exercise the first-launch wizard instead of the checked-in development configuration:

```sh Terminal 1
cd backend
go run . server start --config=./configs/manual-onboarding.yaml
```

```sh Terminal 2
task dev:frontend
```

Open the URL printed by Rsbuild, normally `http://localhost:3000`.
