---
title: Operate Querylane
description: Back up, upgrade, and troubleshoot Querylane. Day-two operations come down to one database and one key.
---

Querylane is a single stateless process in front of one metadata database. Operating it means looking after three things: the **metadata database**, the **instance secret key**, and the **image version**.

## Back up

Back up the metadata database like any PostgreSQL database, and keep the matching `QUERYLANE_INSTANCE_SECRET_KEY` with it. A dump without the key cannot decrypt the instance credentials inside it.

```sh
pg_dump --format=custom --no-owner --no-privileges \
  --file="querylane-$(date -u +%Y%m%dT%H%M%SZ).dump" \
  "$QUERYLANE_DATABASE_DSN"
```

To restore, create an empty database, `pg_restore` into it, and point Querylane at it with the same key. Test this once on an isolated copy before you need it.

If you use embedded PostgreSQL, stop Querylane and copy the data directory (`~/.querylane/pgdata` by default). Move to an external PostgreSQL before backups become important.

What you do not need to back up: Querylane has no local state besides that. Catalog caches and metric samples live in the metadata database and are rebuilt or re-collected automatically if you start fresh — you only lose history and would re-register instances.

## Upgrade

Querylane applies pending metadata migrations when a new version starts, so an upgrade is: back up, change the image tag, start.

1. Read the [release notes](/changelog).
2. Back up the metadata database.
3. Deploy the new image. With several replicas, let the first one finish migrating before the rest start (the Helm chart's default rolling update does this).
4. Confirm `GetConsoleConfig` reports `STATE_READY` and open an instance.

To see what a version will change before deploying it:

```sh
docker run --rm --env QUERYLANE_DATABASE_DSN="$QUERYLANE_DATABASE_DSN" \
  ghcr.io/querylane/querylane:<version> migrate status
```

### Roll back

An older image may not understand a newer schema. To roll back, stop Querylane. **Restore the pre-upgrade backup** into a fresh database, then start the previous image against it. Keep the migrated database around for investigation instead of overwriting it.

## Troubleshoot

Start with the logs; Querylane logs structured JSON and says clearly whether the metadata database or an instance is the problem.

```sh
docker logs --tail 200 querylane           # Docker
kubectl -n querylane logs deploy/querylane # Kubernetes
```

| Symptom | What it means | Fix |
| --- | --- | --- |
| UI shows the setup wizard unexpectedly | No metadata database configured, or its connection failed | Check `QUERYLANE_DATABASE_DSN` / the `database:` section and the logs for the connection error |
| API returns `failed_precondition` | Same as above; the HTTP server is up but the metadata database is not ready | As above |
| `QUERYLANE_INSTANCE_SECRET_KEY must be base64-encoded 32 bytes` | The key is malformed | Generate one with `openssl rand -base64 32` |
| Instances show **credentials unreadable** or **key missing** | The key changed or is not set on this replica | Restore the original key on every replica; rotation is not supported |
| Cannot save a password in the UI | No key configured | Set `QUERYLANE_INSTANCE_SECRET_KEY`, or define the instance in YAML with `password_env` |
| Instance editor is read-only | Instances are defined in the YAML file | Edit the file, or remove the `instances` section to manage them in the UI |
| Instance test fails with a generic error | DNS, network, `pg_hba.conf`, SSL mode, or credentials | Try the same DSN with `psql` from where Querylane runs; inside Docker, `localhost` is the container itself |
| `'server.Config' has invalid keys: limits` | The config uses keys newer than the running image | Upgrade the image or remove the key |
| Embedded PostgreSQL fails to start | Unwritable data directory, busy port, or read-only filesystem | Fix directory ownership, set `embedded.port: 0` (it scans upward automatically from `5433`), mount a writable volume |

Do not paste DSNs, passwords, or the secret key into issues.

## Routine checks

- Restore a backup into a scratch database once in a while; the key must come with it.
- Watch metadata database size: samples are retained for 30 days and pruned automatically.
- Review the PostgreSQL roles you gave Querylane and remove ones you no longer need.
