Querylane currently publishes a rolling preview image. Tagged releases produced by the release pipeline also include self-contained binaries. Until the first binary release is available, use the preview to evaluate the product and pin its digest anywhere repeatability matters.

## Fastest path: Docker

You need Docker and a PostgreSQL server that Querylane can reach. Querylane also offers embedded PostgreSQL, but that path is best for a direct host run rather than a container.

Start a disposable preview:

```sh
docker run --rm \
  --name querylane \
  --publish 127.0.0.1:8080:8080 \
  ghcr.io/querylane/querylane-dev:edge
```

Open `http://localhost:8080`. A fresh container has no metadata database configuration, so Querylane opens the first-launch wizard.

:::warning
`querylane-dev:edge` follows the latest build and can change without notice. This Docker command also removes the container when it stops. Use it for evaluation, not as a durable deployment.
:::

## Download a release binary

Each tagged binary release includes the compiled web application and needs no separate frontend runtime. Open [Querylane releases](https://github.com/querylane/querylane/releases), choose a version, and select the archive for your system:

| System | Archive suffix |
| --- | --- |
| Apple silicon macOS | `darwin_arm64.tar.gz` |
| Intel macOS | `darwin_amd64.tar.gz` |
| ARM64 Linux | `linux_arm64.tar.gz` |
| AMD64 Linux | `linux_amd64.tar.gz` |
| AMD64 Windows | `windows_amd64.zip` |

On macOS or Linux, replace `1.2.3` below with the release version:

```sh
set -eu

version="1.2.3"

case "$(uname -s):$(uname -m)" in
  Darwin:arm64) target="darwin_arm64" ;;
  Darwin:x86_64) target="darwin_amd64" ;;
  Linux:aarch64 | Linux:arm64) target="linux_arm64" ;;
  Linux:x86_64) target="linux_amd64" ;;
  *) echo "Unsupported system: $(uname -s) $(uname -m)" >&2; exit 1 ;;
esac

archive="querylane_${version}_${target}.tar.gz"
release_url="https://github.com/querylane/querylane/releases/download/v${version}"
curl --fail --location --remote-name "${release_url}/${archive}"
curl --fail --location --remote-name "${release_url}/checksums.txt"

checksum_line="$(awk -v archive="$archive" '$2 == archive { print }' checksums.txt)"
if [ -z "$checksum_line" ]; then
  echo "No checksum found for $archive" >&2
  exit 1
fi

if command -v sha256sum >/dev/null 2>&1; then
  printf '%s\n' "$checksum_line" | sha256sum --check
else
  printf '%s\n' "$checksum_line" | shasum --algorithm 256 --check
fi

tar --extract --gzip --file "$archive"
mkdir -p "$HOME/.local/bin"
install -m 0755 querylane "$HOME/.local/bin/querylane"
"$HOME/.local/bin/querylane" --version
"$HOME/.local/bin/querylane" server start --host 127.0.0.1
```

Add `$HOME/.local/bin` to `PATH` if you want to run `querylane` without its full path. Windows users can verify the downloaded ZIP against `checksums.txt`, extract `querylane.exe`, and place it on `PATH`.

## Choose Querylane's storage

The wizard is configuring **Querylane's own metadata database**, not the PostgreSQL server you want to inspect. Choose 1 path:

| Path | Best for | Continue with |
| --- | --- | --- |
| Embedded PostgreSQL | A direct local run or disposable demo | [Embedded PostgreSQL](/get-started/embedded-postgresql) |
| External PostgreSQL | A durable installation | [External PostgreSQL](/get-started/external-postgresql) |
| Manual YAML | Configuration-as-code and environment-backed secrets | [Manual YAML](/get-started/manual-yaml) |

After that database is ready, [register the PostgreSQL instance](/get-started/register-instance) you want Querylane to inspect.

## Build and run from source

Use the source path for contributor work or when you need an unreleased change. Install Go 1.26, Bun 1.3, [Task](https://taskfile.dev/), and Git.

```sh
git clone https://github.com/querylane/querylane.git
cd querylane
task setup
task dev:setup
task dev
```

The development stack starts its own PostgreSQL database, the backend on port `8080`, and the frontend at the URL printed by Rsbuild. To exercise the actual first-launch wizard instead, use the [local preview guide](/get-started/local-preview).

## Verify the server

A successful `GET /` proves that the process is serving the web application:

```sh
curl --fail http://localhost:8080/ > /dev/null
```

After metadata setup is complete, verify the API too:

```sh
curl --fail --request POST \
  --header 'Content-Type: application/json' \
  --header 'Connect-Protocol-Version: 1' \
  --data '{}' \
  http://localhost:8080/querylane.console.v1alpha1.ConsoleService/GetConsoleConfig
```

If the second command reports `failed_precondition`, the server is running but still needs metadata database setup. See [troubleshooting](/get-started/troubleshooting) for startup, connection, and container problems.
