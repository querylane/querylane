Querylane is a self-hosted, PostgreSQL-first admin workspace for people who need to understand more than 1 server. It puts the running system and its catalog in the same place: instance health, sessions, roles, databases, schemas, tables, policies, partitions, triggers, and definitions.

The fastest way to understand Querylane is to connect 1 non-production server you already know, then use it to answer a question whose answer you can verify.

## Reach a useful first session

<Steps>
  <Step title="Start Querylane">
    Use the [quickstart](/get-started) to run the preview and configure Querylane's own metadata database.
  </Step>
  <Step title="Connect a server you understand">
    Register 1 instance, preferably a non-production server with a dedicated read-only login.
  </Step>
  <Step title="Establish a baseline">
    Confirm connection state, server details, health checks, activity, database structure, and role visibility.
  </Step>
  <Step title="Leave with a verified answer">
    Follow the quickstart and compare what Querylane shows with a fact you already know about the server.
  </Step>
</Steps>

## 1 place to answer operational questions

Database tools often split the job in 2: a SQL client for structure and data, then a monitoring tool for the live server. Querylane is designed around the questions that cross that boundary.

- Is this instance healthy, connected, and replicating?
- Which sessions are active, idle in a transaction, waiting, or blocking work?
- Which roles can reach a database, schema, or table, and through what membership path?
- How do tables relate, and what constraints, indexes, policies, partitions, and triggers shape them?
- Can I export or inspect rows without losing the surrounding catalog context?

## What works today

| Area | What you can do |
| --- | --- |
| Instances | Register multiple PostgreSQL servers, inspect connection state, server details, metrics, and health |
| Activity | Inspect live sessions, transaction age, client origin, waits, and blocking relationships |
| Data Explorer | Browse schemas and database objects, map table relationships, inspect table metadata, filter rows, and export data |
| Roles and access | Explore roles, memberships, grants, definitions, and effective access paths |
| Database insights | Review extensions, database health, and query insights |

## A read-first preview

Querylane is deliberately read-first today. It is useful for inspection and operational understanding, but it does not yet replace a mature SQL IDE or every write-heavy PostgreSQL administration workflow. The planned [SQL Workbench and write path](/roadmap) close those gaps in that order, with safety rails before broad mutation support.

Review [Use Querylane](/use-querylane) for the product tour and a comparison with pgAdmin, database IDEs, and ORM-oriented studios.
