<h1 align="center">Querylane</h1>

<p align="center">

## Features

- **One workspace for many servers** — register every PostgreSQL instance you operate and switch between them; connection state, version, capacity, and health checks on one overview.
- **Live activity** — sessions, transaction age, waits, and blocking relationships, so you can see what a server is doing right now.
- **Instance metrics and health** — connections, cache hit ratio, storage, and I/O sampled over time into Querylane's own metadata database.
- **Data Explorer** — browse schemas and objects, inspect columns, indexes, constraints, policies, and triggers, map relationships, filter rows, and export data.
- **Roles and access** — roles, memberships, grants, and an effective-access graph that answers "who can read this table, and through which path?"
- **Database insights** — extensions, query patterns via `pg_stat_statements`, and table-level statistics.
- **Configuration as code** — declare instances in `querylane.yaml` with secrets from environment variables, or manage them in the UI with encrypted storage.
- **Simple to run** — one distroless container serving API and UI on one port; horizontally scalable against a shared metadata database.

Querylane is read-first today. A SQL editor and row editing are [planned](https://docs.querylane.net/roadmap).

## Get started

Try Querylane with demo data in one command. It starts Querylane, its metadata
database, and a demo PostgreSQL server with a live workload generated by
[seeder-buddy](https://github.com/querylane/seeder-buddy). You only need Docker.

```sh
curl -fsSL https://raw.githubusercontent.com/querylane/querylane/main/deploy/quick-start/compose.yaml | docker compose -f - up
```

Open <http://localhost:8080>. Remove everything with `docker compose -p querylane-quick-start down --volumes`.

Let your coding agent do the installation instead:

```sh
npx skills add querylane/querylane
```

### Install guides

| Path | Guide |
| --- | --- |
| Docker — connect to your own PostgreSQL, or add servers to the quick start | [Install with Docker](https://docs.querylane.net/get-started/install-docker) |
| Helm — chart at `oci://ghcr.io/querylane/charts/querylane` | [Install with Helm](https://docs.querylane.net/get-started/install-helm) |
| Kubernetes — zero-dependency trial with `--set devPostgres.enabled=true` | [Install with Helm](https://docs.querylane.net/get-started/install-helm#try-it-on-any-cluster) |
| Production — external metadata PostgreSQL, secrets, authenticated ingress, least-privilege roles | [Deploy Querylane](https://docs.querylane.net/get-started/deploy-querylane) |
| Configuration — `querylane.yaml` and environment variables | [Configure Querylane](https://docs.querylane.net/get-started/configure-querylane) |

> [!WARNING]
> Querylane is a preview and has no built-in authentication. Keep it on a
> private network or behind an authenticating proxy, and read
> [Deploy Querylane](https://docs.querylane.net/get-started/deploy-querylane)
> before giving it production credentials.

## Contributing

Querylane is a Go + React monorepo. Install Go 1.26, Bun 1.3, and [Task](https://taskfile.dev/), then:

```sh
task setup
task dev:setup
task dev
```

See [`AGENTS.md`](AGENTS.md) for repository conventions and
[`docs/release-process.md`](docs/release-process.md) for how releases and images are cut.

### Documentation site

The docs at <https://docs.querylane.net> are built with [Blume](https://useblume.dev/):

```sh
bun install
bun run docs:dev       # local preview
bun run docs:validate  # links and anchors
bun run docs:build
```

`bun run docs:eval` checks whether the docs answer the questions in `evals.yaml`.
It uses the Codex CLI with an OpenAI API key, so install and authenticate Codex
first (`npm install --global @openai/codex`, then `codex login --with-api-key`).
Pull request CI never runs paid evals; use the manual GitHub Actions workflow
`docs-eval` for an on-demand run. The API reference is generated from `proto/`;
run `task proto:generate` after changing an API contract.
